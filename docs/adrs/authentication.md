# ADR-003 認証方式

## Status
Accepted

## Context

SPA + REST API構成であり、将来的にはモバイルアプリや外部サービスからのアクセスも想定している。サーバー側セッションを持たず、スケールしやすい認証方式が必要。

## Decision

- `/auth/login`でユーザー名・パスワードを受け付け、Spring Security 7が認証。
- 認証成功時にHS256署名のJWTを発行（有効期限60分、`sub`・`role`・`exp`を含む）。
- クライアントはJWTをセキュアストレージに保持し、API呼び出し時に`Authorization: Bearer <token>`ヘッダーを付与。
- リフレッシュは再ログインで対応（アクセストークンのみ）。

## Consequences

### 利点

- JWTによりAPIはステートレスにスケールでき、ロードバランサ配下でもセッション共有が不要。
- ユーザー属性（roleなど）をトークンで伝播でき、バックエンドでの認可判定が簡潔。

### 欠点

- トークン盗難に備えてHTTPS強制と保管方法（localStorage/secure cookie）の検討が必要。
- 失効管理（ログアウト、鍵ローテーション）をKey管理ポリシーとして別途定義する必要がある。
